# Reliability Hardening — Design

## Overview

Точечные изменения в существующих модулях. Новых сервисов, зависимостей и форматов файлов не добавляется.

## Components and Interfaces

### CLI

`run_recommendation` выводит предупреждения `parse_blacklist` в `stderr` тем же способом, который уже используется для профилей. Форматы отчётов не меняются.

### Safety policy и проверка игр

`safety_gate` получает дополнительный код `LENGTH_UNKNOWN`. Проверка выполняется только при заданном `max_completion_hours` и отсутствующей оценке. Проверка `Game.name` остаётся вне verdict-политики: это дополнительная проверка целостности внешних данных, а не новое правило GTI.

`Matcher.recommend` завершает отчёт без проверенных рекомендаций, если эталон не подтверждён Store. `steam_batch_filter` добавляет per-game rejection `UNVERIFIED_GAME`. `steam_match_backlog` добавляет признаки подтверждения и запрещает положительный synergy verdict при неподтверждённой стороне. `_resolve_appid` валидирует положительность numeric AppID.

### Storage

`write_json_object` создаёт уникальный временный файл рядом с целевым и заменяет цель через `Path.replace`. Мутирующие операции используют общий `threading.RLock` вокруг read-modify-write. Перед изменением существующего файла tolerant reader вызывается со сбором предупреждений; любые предупреждения чтения превращаются в `ValueError`, поэтому повреждённый источник не перезаписывается. Read-only `load_user_data` сохраняет прежнее поведение.

### Tests

Тесты используют `tmp_path`, monkeypatch и fake HTTP/Pipeline/Transport. Для HTTP-границ применяются fake `httpx.AsyncClient`/stream responses либо существующие публичные интерфейсы без реальной сети. Параллельное хранение проверяется потоками с барьером; тест не полагается на timing sleeps.

## Error Handling

- Некорректная ручная конфигурация: warning при чтении, ошибка при попытке перезаписи повреждённого файла.
- Неподтверждённая игра: явный exclusion/verdict, без положительной рекомендации.
- Неизвестная длительность при активном лимите: `LENGTH_UNKNOWN`.
- Ошибки записи: пробрасываются вызывающему коду; временный файл очищается.

## Testing Strategy

1. Добавить регрессионные тесты и зафиксировать red на исходном коде.
2. Реализовать минимальные исправления до green.
3. Прогнать полный набор, Ruff, CLI smoke и MCP protocol smoke.
4. Проверить diff и отсутствие unintended files.
